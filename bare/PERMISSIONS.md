# 三层权限

目标只有一个：**用户态（EL0）能干的坏事，必须在三个不同的地方各被拦一次**。
任何一层单独都不够，因为每层能看到的“坏事”形状不同。

| 层 | 在哪 | 拦什么 | 拦不住什么 |
|---|---|---|---|
| 一：页表 | `paging.c` | EL0 读写/取指不该碰的页（内核镜像 EL1-only，栈页 UXN，代码页只读） | 合法用户指针里夹着内核地址 |
| 二：异常级 | `vectors.S` + `do_sync` | EL0 的访存/取指故障立即杀线程，且**不**“跳过指令” | 参数合法但语义越权 |
| 三：系统调用 | `syscall.c` `u_ok()` / `u_str()` | 用户递进来的指针必须落在 `[0x10000000, 0x10200000)`、逐页已映射、长度不回绕 | — |

## 第一层：页表

- 用户窗外的地址，EL0 在页表里根本不存在条目 → translation fault。
- 内核区（`0x40000000+`）在 aspace 里是 EL1-only：EL0 访问即 permission fault。
- 代码页 `PG_USER_RX`（只读+可执行）、栈页 `PG_USER_RW`（读写+UXN，不可执行）。
- `pg_map_user()` 只接受用户窗内、4K 对齐、三种受控属性，别的直接 -1。

实测：`user_bad` 读 `0x40000000` →
`esr=0x9200000d`（EC=0x24 低 EL 数据中止，FSC=0b001101 三级权限故障），`far=0x40000000`。

## 第二层：异常级

`do_sync` 用 SPSR 的 M 位分辨来源（EL0t vs EL1h）：

- EL0 的 data abort：判线程死刑（`kthread_exit`），**不修改 ELR**。老代码对任何
  abort 都 `ELR += 4` 跳过，那等于让用户态静默越过保护。
- EL0 的 svc 不污染内核 `svc_seen` 计数（自检数字只数 EL1 自己的 svc）。
- EL0 的 `exit` 才做 TTBR0 回退与地址空间解绑；内核线程的 `exit` 原样走调度。

## 第三层：系统调用

内核对“用户指针”是直接解引用的，而 EL1 读用户 VA 是合法的——所以这一层必须自己校验：

```c
u_ok(p, n)  // 窗内 + 逐页 pg_user_pa 非 0 + p+n 不回绕
u_str(p,dst,cap) // 逐字节 copyin，页边界处重新校验，绝不跟着指针跑出映射
```

- 失败返回 `-2`（EFAULT）并打印 `[kern] user: syscall denied nr=.. ptr=..`。
- `SYS_PUTS` / `SYS_OPEN` 走 `u_str()` 拷进内核缓冲：用户字符串贴页尾、下一页
  未映射时，内核不会替它跑野指针。
- `SYS_WRITE` / `SYS_READ` / `SYS_LIST` 校验整段缓冲（逐页）。
- 内核线程自己 `svc` 时 `g_from_el0=0`，不套这套规则（它传的是内核指针）。

实测：`user_bad2` 把 `0x40000000` 当 puts 参数递进来 →
`[kern] user: syscall denied nr=1 ptr=0x40000000`，返回 -2，随后 exit 1。

## 前提：EL0 必须是可抢占的

三层都建立在“EL0 被公平调度”之上。为此：

- `switch_to` 现在保存/恢复 **DAIF**（线程私有），不再把某个线程的中断屏蔽状态写死。
- `tcb` 带 `l1`，`schedule()` 在切换前恢复**即将运行线程的 TTBR0**；
  两个用户线程互相抢占时各回各的地址空间。
- EL0 用 `SPSR.I=0` 进入，所以时钟中断能进来；`eret` 前的三条 `msr` 仍在临界区里
  （ELR/SPSR/SP_EL0 是系统寄存器，跨抢占点就会被别人覆盖）。

实测：`user` 线程空转 67M 次、期间不发任何 svc，退出时 `preempt=46`
—— 46 拍时钟是在 EL0 里被打进来的，不是靠屏蔽混过去的；
且它在被抢占、让出、再恢复之后仍然打印出 `hello from EL0`
（说明 TTBR0 恢复正确，落回了自己的地址空间）。
